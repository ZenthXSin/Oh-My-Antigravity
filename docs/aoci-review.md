## 作用与适用范围

AOCI-CODE 是本地 Go CLI 与 stdio MCP 服务，为代码库和可选数据库结构保存由 Agent 编写的知识索引。它提供九个 MCP 工具，覆盖规则、全局索引读取、局部检索、条目写入与维护。语义理解和代码执行由宿主 Agent 承担。

`aoci.txt` 声明索引组成，`aoci.meta.txt` 保存标签和格式规则，`aoci.code.txt` 保存代码知识，数据库可另建 Volume。这些文本文件随项目进入 Git，可以跨会话、跨 Agent 使用并审查变更。

每条记录以 FRAS 表达文件职责（F）、强关联（R）、公开接口（A）和关键约束（S）。文件路径和哈希由程序核对，职责及约束由模型阅读实际源码后编写；不能把目录名自动拼成已验证的项目知识。

## 对增强版有价值的机制

| 机制 | 对本项目的用途 | 实施条件 |
|---|---|---|
| 持久化职责、依赖和接口索引 | 换会话后恢复架构认识，减少重复搜索；帮助保持模块边界 | 索引绑定实际源码，重要判断仍核对实现 |
| 源码绑定与陈旧状态 | 用户或其他 Agent 修改代码后，发现需要重读的条目 | 核对内容指纹，不能只相信摘要和 Git 提交号 |
| 增量交付 | 已有有效索引基础时只交付新增、修改和删除的条目 | 保留会话基础身份；基础丢失后重新读取所需范围 |
| 有预算的维护批次 | 完成代码修改后更新受影响知识，避免单次工具结果过大 | 预算控制传输大小，不能静默漏掉剩余条目 |
| 核心逻辑、MCP 与本地化资源分离 | 增强版可保持存储、维护、宿主适配和提示词各自独立 | 通过明确接口组合，避免把全部逻辑堆进钩子 |

源码依据：`engine/mcp.go`、`internal/mcptools/overview_delta_v1.go`、`internal/mcptools/tools_read_refresh.go`、`internal/mcptools/tools_maintain_budget.go`、`docs/agent-integrations.md`。

增量交付的基础在 MCP 宿主会话内存中，跨会话持久的是 Git 索引。维护预算默认按字节控制工具返回大小，不是付费 token 预算；这些机制也不能直接提高上游 API 的缓存命中率。

## 取舍

它的默认流程先读取完整 Whole-Index，并要求交付确认和模型认知声明。作者提到大型项目索引可达到约 300K tokens；本项目默认输入上限是 275K，工具结果还有独立截断限制，因此不能假设全量索引总能装下，也不能直接承诺省多少 token。

适合本项目的方向是预算内的项目概览、任务相关模块检索和有效基础上的增量刷新。采用完整 AOCI 时需遵循其协议，并先验证 Antigravity 的 MCP 交付能力；自行设计按任务读取的模块索引，则应明确属于自有实现，不能宣称已实现 AOCI 的完整认知协议。

模型能回填索引身份或回答抽样挑战，能提供交付和回忆方面的证据，但不足以证明已经完全理解系统。不要把这类流程扩写成每次任务必须重复的长提示词、额外审批和笼统“掌握百分比”。

项目已有原生工具执行和工作流，现有 Goal 保存目标及检查点。知识索引可作为独立 MCP 能力组合接入，不需要替换这些机制或更改模型提供商。AOCI 自身不提供 JS 工具编排运行时，也不会补出原生工作流缺失的 `call_tool` 接口。

## 接入与分发

Antigravity 已能加载本项目的 stdio MCP 插件，具备尝试接入 AOCI 的基础；其文档未列出 Antigravity 专用适配，本轮尚未进行宿主闭环验收。接入时应保留已有规则和 MCP 配置，机器相关的绝对路径只写入本机配置，不能进入公共仓库。
