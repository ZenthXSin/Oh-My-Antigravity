# 多渠道与模型设置

1.4.1 为 Antigravity 2.33.0 的桌面主 Agent 增加渠道聚合。首次安装默认进入本地工作区，无需登录或配置提供商。选择 API 聚合渠道后，按渠道配置服务地址、协议、密钥和模型；选择官方服务时继续按官方流程登录。已有配置缺少新版接入方式字段时，沿用原有官方或聚合模式。模型与模式变更须完全退出并重新启动 Antigravity，使原生模型配置重新加载。

四种协议分别适配 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages 和 Gemini。它们接入桌面主 Agent 的原生工具流程，工具执行继续受原生审批和权限设置控制。渠道服务的模型能力、配额和账单由相应服务决定。

每个模型的最大输入默认 275,000 tokens，最大输出默认 125,000 tokens，均可修改。输入上限通过原生上下文控制生效；输出上限映射到各协议实际请求字段。设置值不能提高服务端本身的上限，需按使用的模型能力调整。

| 协议 | 输出上限字段 |
|---|---|
| OpenAI Chat Completions | `max_completion_tokens` |
| OpenAI Responses | `max_output_tokens` |
| Anthropic Messages | `max_tokens` |
| Gemini | `generationConfig.maxOutputTokens` |

强度滑条显示当前模型实际配置的全部档位，不把所有模型强制映射成相同档位数；标签保留英文。Ultra 档位的粒子向右发射。动画默认遵循系统的减少动画偏好，用户主动点击闪电开关可覆盖系统默认，单独启用或关闭动画。

闪电开关通过原生 `storageService` 保存选择，避免应用本机服务端口变化导致浏览器 `localStorage` 的偏好失效。

渠道配置和密钥保存在接收者本机，不进入源码仓库、截图或安装包。配置服务时使用自己的有效密钥。当前没有真实付费渠道密钥，四协议的真实服务端行为尚未验收，不能把本机流程检查当作付费服务兼容保证。

已在实际运行的 Antigravity 中操作以下流程；渠道端使用本机服务替身：

- 四协议分别完成 `read_file → 原生审批 → 工具结果 → 正确最终回答`。OpenAI Responses 的 encrypted reasoning 和 Anthropic 的 thinking signature 均在原生跨工具轮次中保留。
- 实际拖动滑条选择 Ultra，模型显示 Ultra，渠道收到 `reasoning_effort: ultra`。动画启用时 14 个粒子运行，系统减少动画默认生效时粒子停用。
- 中文与英文双向切换；渠道新建、编辑、删除、获取模型，以及编辑时空密钥保留已保存密钥。
- 275,000／125,000 默认上限和 300,000／64,000 修改值保存。原生模型 catalog 的输入上限为 300,000；Anthropic 实际请求的 `max_tokens` 为 64,000。
- 禁用聚合并重启后恢复原生官方模型，启用并重启后恢复聚合模型。
- 1.4.0 更新安装和完整卸载成功退出。卸载后原厂归档 SHA256 完全恢复，既存渠道密钥、Goal 和会话状态保留。

最终 1.4.0 安装包也完成重新安装，成功退出。动画开关通过完整退出与重启后的原生存储恢复，应用本机端口变化后仍保持开启，14 个粒子继续运行。协议转换另检查了推理签名按渠道、模型与协议隔离、纯文本回合保留、重复同名工具调用的结果 ID 配对，以及 SSE 的 CRLF 跨数据块处理。

最终安装包的完整卸载成功退出：原厂归档与安装前原件 SHA256 完全一致，既存配置、会话状态和四份加密渠道密钥逐项保持原 SHA256，官方可执行文件保留。

这些结果验证原生应用与本机协议转换的闭环；真实服务端对模型、推理档位、媒体和额度的支持仍需使用有效渠道密钥确认。

架构参考为 MIT 项目 [CC Switch](https://github.com/farion1231/cc-switch/tree/6e06607290b805ff2d0b92fa4e6bc69526f5e740)，本项目未直接内置其应用。中文化中仍有少量第三方与服务端动态英文文案；原生工作流环境未开放 `call_tool` 时，实验性 JS 桥仍不能用于真实工具调度。

1.4.1 已完成本机更新安装、无提供商本地工作区启动与重启，以及设置入口操作。独立空白配置无需登录即可进入工作区，添加本机模拟 Gemini 渠道并重启后，完成 read_file、逐次审批与工具结果回传。官方模式使用原生认证及引导页面。Windows EXDEV 替换失败复用原生存储的已有写入回退，其他错误继续上抛；渠道配置也仅为该错误提供回退。安装启动器已验证可写临时目录、PowerShell 模块路径隔离及参数传递。
