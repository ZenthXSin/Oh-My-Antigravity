# Agent 提示词设计

保留 Antigravity 的原生任务、工具、知识核对和上下文恢复，补充持续推进、真实验收与简洁沟通。模型、账号、批准策略和原生工具接口沿用。

接到任务先从用户角度理解动机、期望成果和希望的推进方式，结合明确请求与上下文确定完成标准，再采取行动。推断服从明确指令，不擅自扩大范围；只有影响结果的关键缺失信息才澄清。这些判断用于执行，不例行输出长篇分析。

| 保留或借鉴的行为 | 实现位置 |
|---|---|
| 原生知识仅作线索，改动前核对当前代码与工具 | 常驻工作原则 |
| 交接保留目标、约束、已做工作与下一步 | 工作原则与 Goal 检查点 |
| 持续推进完整目标，后续消息并入原任务 | 工作原则 |
| 完成证据覆盖完整要求 | 工作原则与 Goal 完成工具 |
| 区分进展、真实等待与反复重述 | 工作原则、执行技能与续跑提醒 |

常驻规则精简表达“少说话多做事，有问题必须说”：正常流程少播报，错误、受阻、范围变化或需要用户决定时及时说明。限制无关读取并复用有效结果，把上下文用在判断、执行和必要验证。命令句柄、工作流桥接及 Windows 操作细节放在 `native-execution` 技能中按需阅读；普通短任务不加载通用执行规范。

PreInvocation 对普通无 Goal 请求返回空注入；失败提醒只覆盖对应原生步骤。Goal 每轮补充一次完整目标、验收条件、检查点、下一步、证据及阻碍与续跑计数，剔除内部散列、时间戳等管理字段。Stop 提醒不再复制完整目标，完成或取消的 Goal 不跟随无关普通请求。

验收优先实际使用：启动产品、操作真实流程并观察输入输出。避免例行新增或运行单元、集成及全量测试，不为验收制造替身或复述实现。实际操作覆盖不了明确疑点，或项目明确要求时，才做最小针对性自动检查。必要构建与启动继续执行；文件存在或编译成功不能代替可用证明。

缓存复用通过稳定静态规则与工具定义顺序、减少重复注入、把动态 Goal 状态置于本轮上下文来改善。实际命中率由原生运行时及模型服务决定，不承诺固定百分比。

编码要求直接陈述事实与真实不确定性，减少自我辩护和免责语言。内部代码遵循明确契约，避免重复校验、无依据兼容、静默兜底和吞异常；必要校验集中在外部输入、I/O 与真实不变量的责任边界。

项目结构采用低功能密集度、高内聚和低耦合：公共定义／契约、实现、外部适配及应用组合分别组织。组合层装配依赖，业务逻辑归属具体模块；依赖单向，避免循环依赖和共享可变全局状态。拆分围绕职责边界，避免碎文件、空转抽象与无关全面重构。

已在应用内观察到普通文件任务通过两个原生调用完成创建与读回，未额外加载技能、计划或通用规则；Goal 也完成过保存检查点、自动续跑和原生操作证据闭环。这些观察说明相应小任务流程可用，长任务行为仍需实际使用评估。

原生内置压缩模板未修改，旧会话中的历史提示也不会追溯删除。插件通过工作原则与 Goal 检查点改善交接，独立压缩调用是否采用补充规则由原生运行时决定。关闭插件可通过「自定义 → 已安装」完成，不删除保存的 Goal。参考来源及许可证见项目 README 和第三方声明。
